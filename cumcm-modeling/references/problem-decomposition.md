# 结构拆题与主线识别

把赛题视为一项递进研究，而不是若干互不相关的小题。题目不一定有四问，始终按实际问题数量处理。

## 每问要素

对每一问至少记录：

- 研究对象与场景；
- 输入数据和已知量；
- 状态量、观测量和派生量；
- 未知参数；
- 决策变量；
- 输出目标或评价指标；
- 约束与边界条件；
- 与上一问的继承、放宽或推广关系。

如果无法明确“求什么”和“受什么约束”，暂时不要选择算法。

## 主线候选

优先寻找能贯穿全文的对象：

- 同一核心机理或守恒关系；
- 同一状态变量、概率参数或质量指标；
- 同一评价函数、成本或收益口径；
- 同一几何关系、网络或流程结构；
- 同一数据生成机制；
- 同一决策准则。

如果各问表面上不同，检查是否属于：

```text
理想 → 现实
特例 → 一般
估计 → 决策
确定参数 → 不确定参数
基础模型 → 优化
单阶段 → 多阶段
局部 → 全局
```

## 问题依赖图

为多问赛题画出最小依赖图，标明：

- 哪个参数由前问估计后传给后问；
- 哪个公式或约束被继承；
- 哪个假设在后问被放宽；
- 哪个结果转化为目标函数、阈值或决策规则；
- 哪些问题可以独立求解，哪些必须顺序求解。

不要强行制造递进。如果两问确实独立，应明确说明共享的数据、符号或验证口径，而不是虚构联系。

## 预判后续问题

完成基础问题后主动检查：

1. 哪个假设最可能被放宽？
2. 哪个公式最值得一般化？
3. 哪个参数需要从附件估计？
4. 哪个结果可能变为目标或约束？
5. 哪个误差会影响最终方案？

这些判断用于保持变量和模型口径稳定，不用于提前假定题目答案。
